Construction

0 notes

Bringing an object into existence. For a class type, the constructor creates the object's first, complete state through initialisation: the chosen constructor "is called to initialize the object" ([dcl.init.general]). Construction is the time during that initialisation process, and the object's lifetime only begins once initialisation finishes ([basic.life]).

In building terms: building a home
  1. The plans are approvedthe compilerBefore anything is built, the council checks the plans. Rejected plans are a compilation error, and nothing is built at all.
  2. The land is set asidestorageThe block is reserved before any contractor arrives. Storage is obtained before the constructor runs.
  3. The buildinitialisationThe building work itself is initialisation: the process that gives the house its first, complete state. Our contractors are the constructor, the crew who carry that work out. Construction is the time the contractors are on site.
  4. Structure firstmembers, in declared orderFootings, slab, then frame, in the order the plans fix, each built to the spec written on the plans. Each member is initialised in declared order, using its default value, like Texture = nullptr.
  5. The fit-outthe constructor bodyInterior work once the frame is standing. Every member already exists by now.
  6. Handoverlifetime beginsThe moment the contractors finish, the keys are handed over and the owners move in. There's no inspection step in between (unlike a real domestic build).
  7. The crew walks offan exceptionIf something goes wrong mid-build, the only way to stop the handover is for the crew to walk off. Then nobody ever moves in.
  8. Utilities connected and inspectedLoad()Inspections that pass or fail come later, once the owners live there. If the connection fails, Load() logs an error and returns false, while the house itself still stands.
Learnt: .PADEL · See also: Initialisation, Smart pointers, Dangling pointer

I

Initialisation

0 notes

The process that gives an object its initial value ([dcl.init.general]). For a class type, the chosen constructor carries it out: each member is initialised in the order it is declared, whatever order the initialiser list uses, and then the constructor body runs ([class.base.init]). The object's lifetime begins once that is complete ([basic.life]), so an Init() or Load() method called afterwards is not initialisation in the standard's sense: it runs on an object that is already alive.

When Init() or Load() runs on the living object:

  • Called once and it succeeds: the object goes from its safe empty state to holding its resource.
  • It fails: it logs the error and returns false. Written well, it leaves the object in the same safe empty state, so the caller decides what to do next.
  • Called again without Release() first: the old resource is overwritten and leaks, unless Load() releases it first.
  • Called after Release(): it works, because the object is still alive. Release() only returned what the object pointed to.
  • Its dependency isn't ready yet, such as no renderer: it must check and fail cleanly. That's why .PADEL loads in Game::Initialize(), after the renderer exists.
  • Never called: every other method must cope with the empty state, such as Draw() skipping a null texture.
  • Called after the destructor has run: undefined behaviour: calling a member function on an object outside its lifetime ([basic.life]).
In building terms: connecting the utilities
  1. The owners have moved inthe object is aliveThe house is built and lived in. Load() isn't building it: it's connecting the power afterwards.
  2. Power connectedsuccess, trueThe electrician fits the meter and the lights come on. The resource is acquired.
  3. The inspection failsfalse and a logThe inspector writes a report and leaves the power off. The house still stands, and the owners decide who to call next.
  4. A second meter, the first never removeda leakFitting a new meter without taking out the old one leaves you paying for a meter nobody reads. Disconnect first, then connect.
  5. Disconnect, then reconnectRelease(), then Load()Taking the meter out doesn't knock the house down. A new one can go in any time.
  6. The grid isn't built yeta missing dependencyNo electrician can connect to a substation that doesn't exist. Check first, and only book the job once the grid is live.
  7. Power never connectedLoad() never calledThe owners live by candlelight, so nothing in the house may assume the lights work.
  8. The house has been demolishedundefined behaviourSending an electrician to an empty lot. There's nothing defined to connect to.
